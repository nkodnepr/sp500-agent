# Stock Agent — Telegram-бот для анализа акций

Бот анализирует акции из твоего личного списка отслеживания (watchlist),
строит прогноз на 1 неделю / 2 недели / 1 месяц / 3 месяца и присылает
рекомендации BUY / SELL / HOLD. Бот **не покупает и не продаёт акции сам** —
только анализирует и уведомляет.

## ⚠️ Важная оговорка

Это baseline-система на технических индикаторах. Она не гарантирует
точность прогнозов — рынок частично непредсказуем. Перед тем как доверять
сигналам реальными деньгами, обязательно:
1. Прогоните backtest на исторических данных
2. Сравните результаты с простым бенчмарком (buy & hold S&P 500)
3. Используйте сигналы как один из факторов принятия решения, а не как
   единственный источник истины

```bash
python telegram_bot.py
```

Бот запустится и будет работать, пока открыт терминал (для постоянной
работы 24/7 см. раздел "Деплой на сервер" ниже).

## Команды бота

| Команда | Действие |
|---|---|
| `/start` | приветствие и список команд |
| `/add AAPL` | добавить тикер в свой список отслеживания |
| `/remove AAPL` | убрать тикер из списка |
| `/list` | показать текущий список |
| `/check AAPL` | разовый анализ прямо сейчас (не дожидаясь расписания) |
| `/history` | последние 10 отправленных сигналов |
| `/backtest AAPL` | проверка стратегии на исторических данных (~3 года), сравнение с Buy & Hold |
| `/accuracy` | честная точность прошлых сигналов — сверка прогнозов с реальными ценами |
| `/retrain AAPL` | принудительно переобучить модель прямо сейчас (не дожидаясь недельного цикла) |

Ежедневно в заданное время (по умолчанию 9:30, настраивается в `.env`)
бот автоматически анализирует все тикеры из твоего списка и присылает
уведомление, только если сигнал BUY или SELL (чтобы не спамить каждый день).

## Как это работает технически

1. **data_fetcher.py** — загружает 5 лет дневных котировок через yfinance
2. **features.py** — считает технические индикаторы (SMA, RSI, MACD,
   Bollinger Bands, волатильность, моментум)
3. **fundamentals.py** — загружает фундаментальные показатели (рост
   выручки год к году, чистая маржа, ROE, долг/капитал) из годовой
   отчётности и присоединяет их к дневным данным с привязкой по датам
   публикации отчёта (point-in-time), чтобы не допустить утечки будущего
4. **market_context.py** — добавляет относительную силу акции против
   S&P 500 (20/60 дней) как обучающий признак, плюс определяет режим
   рынка (бычий/медвежий/боковой) для ограничивающей логики в сигнале
5. **model.py** — для каждого из 4 горизонтов (1н/2н/1м/3м) обучается
   отдельный RandomForestClassifier на 16 признаках (10 технических +
   2 рыночных + 4 фундаментальных), предсказывающий класс
   (рост/падение/нейтрально) с оценкой вероятности (confidence),
   конкретной ценовой целью, диапазоном и уровнями риска (ATR-based
   стоп-лосс/тейк-профит из risk_management.py)
6. **signal_logic.py** — если 3+ из 4 горизонтов согласованно указывают
   на рост/падение и уверенность модели выше порога — формируется
   сигнал BUY/SELL; медвежий рынок или резко противоречащие новости
   поднимают планку до единогласия (4/4) или понижают сигнал до HOLD;
   приближающаяся отчётность (earnings.py) добавляет явное предупреждение
7. **telegram_bot.py** — по расписанию прогоняет весь watchlist каждого
   пользователя и присылает только значимые сигналы

## Прогноз цены по горизонтам

Для каждого из 4 горизонтов (1 неделя / 2 недели / 1 месяц / 3 месяца)
агент выдаёт не абстрактную "уверенность", а конкретный ценовой ориентир:

```
• 1 месяц: ↑ $203.00–$214.60 (+6.5%, увер. 65%)
```

- **Диапазон цены** строится на исторической волатильности исходов того
  же класса (рост/падение/нейтрально) для этого тикера — если раньше
  такие движения сопровождались большим разбросом, диапазон шире.
  Это статистическая оценка, не гарантия — цена вполне может выйти за
  пределы диапазона, особенно на новостных шоках
- **Ключевые факторы** — под прогнозом показываются 3 признака
  (индикатора), которые сильнее всего повлияли на решение модели
  (`feature_importances_` у RandomForest), с их текущими значениями.
  Например: *"момент за 60 дней (+0.21), цена выше SMA200 (+0.22)"* —
  это превращает прогноз из "чёрного ящика" в объяснимый: видно, ПОЧЕМУ
  модель так считает, а не только ЧТО она предсказывает

## Фундаментальные данные

Технические индикаторы (RSI, MACD, скользящие средние) хорошо ловят
краткосрочные движения (1-2 недели), но для горизонта в 1-3 месяца
важнее фундаментальное здоровье компании. Добавлены 4 метрики:

- **revenue_growth_yoy** — рост выручки год к году
- **net_margin** — чистая рентабельность (Net Income / Revenue)
- **roe** — рентабельность собственного капитала
- **debt_to_equity** — долговая нагрузка (Долг / Капитал)

**Важный технический момент (point-in-time correctness):** каждая
метрика привязывается не к дате окончания отчётного периода, а к дате,
когда отчёт РЕАЛЬНО стал публично доступен (+90 дней — типичная
задержка публикации 10-K/10-Q). Без этого при обучении/бэктесте модель
"видела" бы квартальные результаты за 1-2 месяца до их фактической
публикации — грубая, но частая ошибка, которая рисует обманчиво хорошие
результаты бэктеста, не воспроизводимые в реальной торговле.

**Ограничение бесплатного источника:** yfinance даёт глубину годовой
отчётности примерно на 4 года назад. Для более длинной истории
(нужна для качественного backtest на 10+ лет) потребуется платный
источник данных, например SEC EDGAR API с полным архивом отчётности.

В команде `/check AAPL` теперь также показывается снимок последних
известных фундаментальных показателей — для контекста, на основании
чего строится долгосрочный прогноз.

## Рыночный контекст, риск-менеджмент и отчётность

Три дополнения делают агента ближе к тому, как рассуждает реальный
аналитик — не просто "паттерн в графике этой акции", а полная картина:
рынок в целом, риск сделки и известные источники повышенной неопределённости.

**Относительная сила против рынка (`market_context.py`)** — модель теперь
знает не только как ведёт себя сама акция, но и обгоняет ли она рынок
(excess return против S&P 500 за 20 и 60 дней). Это отделяет собственную
силу акции ("alpha") от того, что "просто весь рынок растёт" ("beta") —
признаки участвуют в обучении наравне с техническими и фундаментальными.

**Режим рынка** — определяется по SPY (цена выше/ниже 200-дневной средней
+ моментум): бычий / медвежий / боковой. Работает как ограничивающий
фактор в `signal_logic.py`: BUY на медвежьем рынке требует ЕДИНОГЛАСНОГО
согласия всех 4 горизонтов (4/4, а не обычных 3/4) — планка доказательств
выше, когда контекст против сделки.

**Риск-менеджмент (`risk_management.py`)** — рекомендация теперь не
заканчивается на "BUY", а включает:
- **Стоп-лосс и тейк-профит** на основе ATR (Average True Range —
  стандартная мера волатильности, учитывающая гэпы)
- **Соотношение риск/прибыль** (например, 1:1.7)
- **Рекомендуемый размер позиции** — по формуле фиксированного риска
  (по умолчанию не более 1% капитала на сделку), так что срабатывание
  стоп-лосса ограничивает убыток заданным процентом, а не случайной суммой

**Предупреждение об отчётности (`earnings.py`)** — если в горизонт
прогноза попадает дата ближайшей квартальной отчётности, сообщение явно
предупреждает об этом: отчётность — один из немногих моментов, когда цена
может резко скакнуть по причинам, которые технический анализ по
определению не предсказывает (реакция на неожиданность, а не на паттерн).

## Sentiment-анализ новостей (FinBERT)

FinBERT — модель BERT, дообученная на финансовых текстах для классификации
тональности новостей (Positive/Negative/Neutral). Работает иначе, чем
фундаментал и техника: это **живой (real-time) модификатор** итогового
сигнала, а не признак для обучения модели.

**Почему не признак для обучения:** бесплатных источников с историческим
архивом новостей за несколько лет с точной привязкой по датам не
существует (в отличие от котировок и годовой отчётности). yfinance даёт
только последние ~10-20 новостей без глубины. Обучать модель на этом
означало бы либо утечку данных, либо обучение почти всегда на нулевом
значении — оба варианта хуже честного использования sentiment только
"здесь и сейчас".

**Как влияет на решение:** если технический анализ даёт уверенный BUY,
но свежие новости резко негативны (score < -0.3) — сигнал понижается до
HOLD. Аналогично для SELL при резко позитивных новостях. Sentiment не
создаёт сигнал сам по себе — только тормозит уже принятое решение при
явном противоречии, чтобы не покупать/продавать вопреки очевидным
свежим новостям, которые модель, обученная на исторических котировках,
не видит.

**Установка:** требует `transformers` и `torch` (см. `requirements.txt`,
помечены как опциональные). Без них бот работает нормально — просто
sentiment всегда нейтрален (0.0), сигналы формируются только на
технике и фундаментале. Первая загрузка модели FinBERT — это скачивание
~400 МБ весов, происходит один раз при первом реальном использовании.

```bash
pip install transformers torch
```

## Кэширование моделей и еженедельное автопереобучение

Раньше RandomForest переобучался заново при КАЖДОМ вызове прогноза — при
каждом `/check` и при каждом ежедневном прогоне по всем тикерам всех
пользователей. Это расточительно: рыночные закономерности не меняются
настолько быстро, чтобы требовать переобучения каждый день.

Теперь (`model_store.py`):
- Модели обучаются **раз в неделю** (по умолчанию — воскресенье, 03:00
  по времени сервера) отдельным планировщиком `weekly_retrain_job`,
  который проходит по всем тикерам из watchlist всех пользователей
- Обученные модели сохраняются на диск (`models_cache/<TICKER>/`) вместе
  с датой обучения
- В течение недели `/check` и ежедневный анализ используют кэш — это
  в разы быстрее, чем обучение с нуля (в тестах — ускорение ~8x)
- Если кэш старше 7 дней или отсутствует — модель обучается автоматически
  "на лету" при следующем запросе, никакого ручного вмешательства не
  требуется
- Команда `/retrain AAPL` позволяет принудительно переобучить конкретный
  тикер прямо сейчас, не дожидаясь недельного цикла

## Честная оценка точности (`/accuracy`)

Модель может "быть уверена на 70%" и при этом стабильно ошибаться —
уверенность модели (confidence) и реальная точность прогнозов часто
расходятся. Единственный способ узнать правду — сверить прошлые
прогнозы с тем, что случилось на самом деле.

Как это работает (`accuracy.py`):
1. Каждый раз, когда бот присылает сигнал (через `/check` или ежедневный
   анализ), прогноз по всем 4 горизонтам сохраняется в БД
   (`signals_history`) вместе с ценой на момент сигнала
2. Команда `/accuracy` проходит по всей истории сигналов пользователя и
   для каждого горизонта, по которому уже прошло достаточно календарного
   времени (например, для 1-месячного прогноза — не раньше чем через
   месяц), подгружает фактическую цену на эту дату
3. Сравнивает направление, которое предсказала модель, с тем, что
   произошло по факту — и считает долю верных предсказаний по каждому
   горизонту
4. Отдельно считает **практическую эффективность** — сколько из
   BUY/SELL сигналов на горизонте 1 месяц оказались реально прибыльными

Сигналы, по которым горизонт ещё не наступил, честно пропускаются, а не
додумываются — если прогноз на 3 месяца сделан неделю назад, "оценивать"
его пока нечем.

**Как читать результат:** случайное угадывание направления даёт ~50%.
Если точность заметно ниже — сигналам модели по этим тикерам пока не
стоит доверять реальными деньгами, независимо от того, что показывает
поле "уверенность" в самом сигнале.

## Деплой через GitHub и Render

### Шаг 1. Залить проект в GitHub

```bash
cd stock-agent
git init
git add .
git commit -m "Initial commit: stock agent bot"
```

`.gitignore` уже настроен — файл `.env` с вашим токеном в репозиторий не попадёт.

Создайте пустой репозиторий на [github.com/new](https://github.com/new)
(без README/gitignore — они уже есть локально), затем:

```bash
git remote add origin https://github.com/<ваш-username>/stock-agent.git
git branch -M main
git push -u origin main
```

### Шаг 2. Подключить репозиторий к Render

1. Зарегистрируйтесь на [render.com](https://render.com), войдите через GitHub
2. **New +** → **Blueprint**
3. Выберите свой репозиторий `stock-agent` — Render автоматически найдёт
   `render.yaml` и предложит создать описанный в нём Background Worker
4. При создании Render попросит ввести `TELEGRAM_TOKEN` вручную (он
   помечен `sync: false` в render.yaml именно поэтому — чтобы не хранить
   секрет в репозитории)
5. Нажмите **Apply** — Render соберёт окружение (`pip install -r requirements.txt`)
   и запустит `python telegram_bot.py`

**Важно про тариф:** Background Worker не входит в бесплатный план Render
(нужен от ~$7/мес). Free tier есть только у Web Service, но он "засыпает"
после 15 минут простоя — для бота с постоянным опросом Telegram (long
polling) это означает разрывы связи, поэтому для стабильной работы нужен
именно Worker.

**Важно про диск:** `render.yaml` уже подключает постоянный диск
(`/data`, 1 ГБ) и направляет туда базу (`watchlist.db`) и кэш моделей
(`models_cache/`) через переменные `DB_PATH` и `MODELS_CACHE_DIR`. Без
этого диска данные стирались бы при каждом передеплое — с ним watchlist
и обученные модели переживают обновления кода.

### Шаг 3. Проверить, что бот отвечает

Откройте Telegram, найдите своего бота, отправьте `/start`. Логи запуска
и работы бота смотрите во вкладке **Logs** в Render Dashboard — там же
видно ошибки, если что-то пошло не так (например, неверный токен).

## Backtest — проверка стратегии на истории

Модуль `backtest.py` прогоняет стратегию по историческим данным методом
**walk-forward**: на каждую точку ребалансировки (по умолчанию раз в месяц)
модель обучается ТОЛЬКО на данных ДО этой даты — без заглядывания в
будущее (это частая ошибка бэктестов, дающая обманчиво хорошие цифры).

Симулируется портфель: покупка на BUY-сигнал, продажа на SELL-сигнал,
удержание позиции на HOLD. Результат сравнивается со стратегией
"купить и держать" (buy & hold) — обязательным бенчмарком.

Запуск из командной строки:
```bash
python backtest.py AAPL
python backtest.py AAPL --start 2019-01-01 --capital 10000 --save-chart
```

Метрики в отчёте:
- **Итоговая доходность** и **CAGR** (среднегодовая доходность)
- **Sharpe ratio** — доходность с поправкой на риск (волатильность).
  Выше — лучше; Sharpe стратегии ниже, чем у Buy & Hold, обычно означает,
  что дополнительная сложность стратегии не окупается
- **Max drawdown** — максимальная просадка портфеля от пика до дна.
  Критично для оценки психологической и финансовой переносимости риска
- **Win rate** — доля прибыльных сделок из закрытых пар BUY→SELL

Через Telegram доступна команда `/backtest AAPL` — она использует те же
расчёты, но с уменьшенным периодом (~3 года) ради скорости ответа бота.

**Как читать результат:** если стратегия систематически проигрывает
Buy & Hold по доходности с поправкой на риск (Sharpe) — сигналы модели
на этом тикере пока не дают реального преимущества, и полагаться на них
не стоит. Это нормальный и ожидаемый исход для baseline-модели на старте;
задача бэктеста — не дать красивую цифру, а честно показать, работает
стратегия или нет, прежде чем на неё полагаться.

## Следующие шаги для улучшения

- Для более длинной истории фундаментальных данных (10+ лет для
  качественного backtest) — перейти на SEC EDGAR API вместо yfinance
- Учитывать sentiment и рыночный режим в backtest.py — сейчас walk-forward
  бэктест использует только техно-фундаментальные признаки модели, а
  режим рынка/новости добавляются лишь в живом прогнозе
- Секторальная относительная сила (сравнение не только с S&P 500, но и с
  ETF своего сектора, например XLK для технологий) — точнее отделяет
  "сила отрасли" от "сила конкретной компании"
- Добавить графики (equity curve, распределение точности по тикерам)
  прямо в Telegram через отправку изображений
- Рассмотреть более продвинутые модели (LightGBM, LSTM) после того, как
  `/accuracy` покажет, что baseline на RandomForest даёт value
