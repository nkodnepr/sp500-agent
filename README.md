# Stock Agent — аналитический агент по акциям США

Агент анализирует акции из личного списка отслеживания (watchlist),
строит прогноз на 1 неделю / 2 недели / 1 месяц / 3 месяца и даёт
рекомендации BUY / SELL / HOLD с ценовыми ориентирами, риск-уровнями и
объяснением, на чём основан прогноз. Агент **не покупает и не продаёт
акции сам** — только анализирует и рекомендует.

Один и тот же аналитический движок доступен в двух интерфейсах —
выбирайте под свой сценарий:

| | Telegram-бот (`telegram_bot.py`) | Настольное приложение (`desktop_app.py`) |
|---|---|---|
| Когда удобнее | Хочется получать уведомления на телефон, не открывая ничего специально | Работаете за компьютером, не нужна интеграция с мессенджером |
| Работа в фоне | Да, постоянно (нужен деплой на сервер/Render) | Нет — запускается вручную, когда нужно |
| Установка | Требует Telegram-бота и деплоя (см. ниже) | `python desktop_app.py` — и всё |
| Автосигналы по расписанию | Да (ежедневно) | Нет — сканирование по кнопке |

Оба интерфейса используют одну и ту же БД (`watchlist.db`) и один и тот
же кэш моделей — можно пользоваться и тем, и другим одновременно.

## ⚠️ Важная оговорка

Это baseline-система на технических индикаторах. Она не гарантирует
точность прогнозов — рынок частично непредсказуем. Перед тем как доверять
сигналам реальными деньгами, обязательно:
1. Прогоните backtest на исторических данных
2. Сравните результаты с простым бенчмарком (buy & hold S&P 500)
3. Используйте сигналы как один из факторов принятия решения, а не как
   единственный источник истины

## Настольное приложение — быстрый старт

**Windows — проще всего:** дважды кликните `run_windows.bat`. Он сам
создаст виртуальное окружение, поставит зависимости (при первом запуске,
дальше — быстро) и откроет программу. Нужен только установленный Python
(с [python.org](https://www.python.org/downloads/), галочка "Add Python
to PATH" при установке).

**macOS — так же просто:** дважды кликните `run_macos.command` в Finder.
Он тоже сам создаст окружение, поставит зависимости и откроет программу.
Если macOS откажется запускать файл (он скачан из интернета) — правый
клик по файлу → «Открыть» → «Открыть». На Linux тот же скрипт
запускается из терминала: `bash run_macos.command`.

**Вручную (любая ОС):**
```bash
cd stock-agent
python3 -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements-desktop.txt
python desktop_app.py
```

На Linux, если `tkinter` не установлен (входит в стандартную библиотеку,
но иногда требует отдельного системного пакета):
```bash
sudo apt install python3-tk        # Ubuntu/Debian
sudo dnf install python3-tkinter   # Fedora
```
На macOS, если Python установлен через Homebrew, `tkinter` тоже идёт
отдельным пакетом (в отличие от установщика с python.org):
```bash
brew install python-tk@3.13     # версия должна совпадать с вашим Python
```
На Windows и macOS с официальным установщиком python.org `tkinter` уже
есть — ничего доустанавливать не нужно.

**Что внутри окна:**
- **Список отслеживания** (слева) — добавление/удаление тикеров, работает
  через ту же БД, что и Telegram-версия
- **Вкладка "Анализ"** — полный разбор по одному тикеру: прогноз цены по
  4 горизонтам, ключевые факторы решения, фундаментал, режим рынка,
  новостной фон, рекомендация, уровни риска
- **Вкладка "Скан списка"** — прогоняет весь watchlist разом, показывает
  только значимые сигналы (BUY/SELL) в таблице
- **Вкладка "S&P 500"** — двухэтапный скрининг всего индекса (~500
  компаний), не только тикеров из watchlist — подробности в разделе
  ["Скрининг S&P 500"](#скрининг-sp-500-500-компаний) ниже
- **Вкладка "Бэктест"** — тот же walk-forward бэктест против Buy & Hold,
  что и `/backtest` в боте
- **Вкладка "Честная точность"** — сверка прошлых сигналов с реальными
  ценами, тот же механизм, что и `/accuracy`
- Кнопка **"Переобучить все модели"** — принудительное переобучение
  (обычно происходит автоматически при устаревании кэша > 7 дней — это
  и есть самообучение, см. раздел "Кэширование моделей" ниже)

Все долгие операции (анализ, скан, бэктест, переобучение, скрининг
S&P 500) выполняются в фоновом потоке — окно не зависает во время расчётов.

**Оформление подстраивается под систему.** Тема (светлая/тёмная)
определяется по фактической яркости фона окна, а не по названию ОС, и
цвета берутся из соответствующей палитры — иначе подзаголовки и
приглушённый текст, подобранные под белый фон, на тёмной теме почти
сливались бы с ним. Шрифты тоже выбираются по платформе: Segoe UI и
Consolas существуют только на Windows, а Tkinter при отсутствии
семейства молча подставляет своё — из-за этого колонки прогноза цены,
рассчитанные на монопропорциональный шрифт, теряли выравнивание на
macOS и Linux.

**Архитектура:** `desktop_engine.py` содержит всю бизнес-логику (не
зависит от Tkinter, покрыт тестами в `tests/test_desktop_engine.py`),
`desktop_app.py` — только отображение. Если понадобится другой GUI
(например, PyQt) — переиспользуйте `desktop_engine.py` без изменений.

## Скрининг S&P 500 (500 компаний)

Кроме ручного watchlist, можно просканировать весь индекс S&P 500 целиком
— вкладка **"S&P 500"**. Работает в два этапа, и это принципиально:

**Почему не просто "полный анализ всех 500 сразу":** полный анализ одной
акции (обучение модели по 4 горизонтам + фундаментал + sentiment + риск-
уровни — всё, что делает `build_full_analysis`) занимает до минуты. Для
500 компаний это часы — непрактично для разового запуска и рискует
упереться в ограничения источника котировок. Поэтому используется
двухэтапный подход, стандартный в квант-скрининге:

1. **Быстрый технический отбор** (`sp500_screener.py`) — один batch-
   запрос котировок сразу по всем ~500 тикерам (`fetch_history_bulk`,
   на порядок быстрее последовательных запросов) + простой технический
   скор (моментум на 20 и 60 дней, положение цены относительно 50- и
   200-дневных средних, RSI) без обучения ML-модели. Занимает обычно
   несколько минут — зависит от скорости интернета и отклика источника
   данных.
2. **Полный анализ шорт-листа** — top-N самых технически "бычьих" и
   top-N самых "медвежьих" кандидатов по итогам этапа 1 проходят уже
   настоящий, полный анализ — тот же, что и для watchlist, с прогнозом
   цены, риск-уровнями и итоговым сигналом BUY/SELL/HOLD. Число
   кандидатов (N) настраивается в интерфейсе. Значимые сигналы
   логируются в общую историю — участвуют в честной оценке точности
   (вкладка "Точность") наравне с сигналами из watchlist.

**Список компаний S&P 500** загружается с Wikipedia (обновляется
сообществом при изменениях состава индекса). Если загрузить не удалось
(нет интернета, изменился формат страницы) — используется небольшой
резервный список (50 крупнейших компаний), и интерфейс **явно
предупреждает**, что это неполный список, а не тихо подменяет 500
компаний на 50.

**Быстрый скор — не замена полному анализу.** Это грубый технический
фильтр для сужения 500 компаний до управляемого числа кандидатов,
которые уже стоит разбирать подробно. Не принимайте решения на основе
одного только быстрого скора без полного анализа шорт-листа.

## Установщик для Windows (Python не нужен)

Собирается два файла, и они для разных случаев:

| | `StockAgent-Setup.exe` | `StockAgent.exe` |
|---|---|---|
| Что это | Установщик | Портативная версия одним файлом |
| Кому | Человеку без технических навыков | Себе, для быстрой проверки |
| Что делает | Ставит программу, создаёт ярлык на рабочем столе и в меню Пуск, добавляет пункт в «Установка и удаление программ» | Ничего не устанавливает — скопировал и запустил |
| Права администратора | Не нужны (установка в папку пользователя) | Не нужны |

**Передавать другому человеку нужно `StockAgent-Setup.exe`** — он
запускает его двойным кликом, нажимает «Далее» и получает обычную
программу с ярлыком. Ни Python, ни консоль, ни распаковка архивов не
требуются.

### Способ 1 (рекомендуется): собрать на GitHub, без Windows и Python

Если у вас нет Windows-машины (например, вы на Mac) — пусть сборку
выполнит GitHub на своей Windows-машине в облаке, бесплатно.

1. Убедитесь, что проект залит в репозиторий на GitHub (см. раздел
   ["Деплой через GitHub и Render"](#деплой-через-github-и-render) —
   там же есть инструкция `git push`, если ещё не делали)
2. Откройте репозиторий на github.com → вкладка **Actions**
3. Слева в списке workflow'ов — **"Build Windows installer"**
4. Кнопка **"Run workflow"** справа → ещё раз "Run workflow" в
   появившемся меню
5. Подождите 10-20 минут (обновится статус на зелёную галочку ✅)
6. Откройте этот запуск → внизу страницы раздел **Artifacts** →
   скачайте `StockAgent-Setup-windows.zip` (и при желании
   `StockAgent-portable-windows.zip`)
7. Распакуйте — внутри готовый `StockAgent-Setup.exe`

Ни Windows, ни Python на вашем компьютере в этом сценарии не нужны —
всё происходит на серверах GitHub.

### Способ 2: собрать локально на Windows (нужен Python)

**Портативную версию:** дважды кликните `build_windows.bat`. Python
нужен только для сборки — готовый `.exe` потом работает без него.

**Установщик** дополнительно требует [Inno Setup](https://jrsoftware.org/isdl.php):
```bat
python build_exe.py --onedir
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer\StockAgent.iss
```
Результат — `dist_installer\StockAgent-Setup.exe`.

### Способ 3: вручную (любая ОС)

```bash
pip install -r requirements-desktop.txt -r requirements-build.txt
python build_exe.py            # один файл
python build_exe.py --onedir   # папкой (основа установщика)
```

**Важное ограничение способов 2 и 3:** PyInstaller не кросс-компилирует
— собирать `.exe` для Windows нужно НА WINDOWS (не в WSL, не в Docker на
Linux, не на Mac). Способ 1 (сборка на GitHub) этого ограничения не
имеет — там используется настоящая Windows-машина в облаке независимо
от того, с какой ОС вы сами работаете.

Размер результата — порядка 250-400 МБ: внутрь упакованы pandas, numpy и
scikit-learn, для такой сборки это нормально. Опциональный слой FinBERT
(`torch`, `transformers`, ~2 ГБ) в сборку намеренно **не включается** —
см. `EXCLUDES` в `build_exe.py`; без него sentiment остаётся нейтральным,
всё остальное работает как обычно.

### Куда сохраняются данные

Список отслеживания (`watchlist.db`) и кэш обученных моделей хранятся в
пользовательской папке данных, ОТДЕЛЬНО от самой программы:

| ОС | Папка |
|---|---|
| Windows | `%LOCALAPPDATA%\StockAgent` |
| macOS | `~/Library/Application Support/StockAgent` |
| Linux | `~/.local/share/StockAgent` |

Так сделано потому, что установленная программа лежит в каталоге
программ: он может быть недоступен для записи, а при удалении стирается
целиком. Практическое следствие — **удаление или переустановка программы
не стирает список акций и обученные модели**.

Исключение — портативный сценарий: если рядом с `StockAgent.exe` уже
лежит `watchlist.db` (так работали прошлые версии), программа продолжит
использовать именно его, чтобы обновление не выглядело как потеря
данных. Переносите такой `.exe` на другой компьютер вместе с этими
файлами.

### Частые проблемы при сборке

- **Антивирус блокирует готовый .exe** — частая ложная тревога у
  однофайловых (`--onefile`) сборок PyInstaller, не специфична для этого
  проекта. Откройте `build_exe.py` и замените `--onefile` на `--onedir`
  — результат станет папкой с файлами вместо одного exe, но реже
  триггерит антивирусы. Либо добавьте exe в исключения антивируса.
- **`ModuleNotFoundError` при запуске готового exe** — какой-то пакет
  использует импорты, которые PyInstaller не смог обнаружить
  автоматически. В `build_exe.py` уже добавлен `--collect-all` для
  самых проблемных пакетов (sklearn, scipy, pandas); если
  ошибка всё равно возникла — добавьте `--collect-all=<имя_пакета>` для
  указанного в ошибке модуля и пересоберите.
- **Долгий запуск exe (несколько секунд)** — нормально для `--onefile`
  режима: при каждом запуске файл распаковывается во временную папку.
  Если критично — используйте `--onedir` (быстрее стартует, но не один файл).
- **Сборка занимает долго / много места** — да, `--collect-all` для
  четырёх тяжёлых пакетов увеличивает время и размер сборки. Это
  осознанный компромисс в пользу того, чтобы exe гарантированно
  заработал с первого раза, а не потребовал повторных попыток с
  добавлением недостающих hidden-imports по одному.

## Установка Telegram-бота

```bash
cd stock-agent
python3 -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Опционально, для sentiment-анализа новостей (FinBERT — тяжёлые зависимости, см. раздел ниже):
```bash
pip install -r requirements-sentiment.txt
```

## Настройка

1. Создайте бота через [@BotFather](https://t.me/BotFather) в Telegram,
   получите токен
2. Скопируйте `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
3. Впишите свой `TELEGRAM_TOKEN` в `.env`
4. **Рекомендуется:** узнайте свой числовой Telegram user_id (напишите
   боту [@userinfobot](https://t.me/userinfobot)) и впишите его в
   `ALLOWED_TELEGRAM_USER_IDS` в `.env` — без этого бот отвечает любому
   пользователю Telegram, который его найдёт (подробности в разделе
   "Безопасность" ниже)

## Запуск

```bash
python telegram_bot.py
```

Бот запустится и будет работать, пока открыт терминал (для постоянной
работы 24/7 см. раздел "Деплой на сервер" ниже).

## Команды бота

| Команда | Действие |
|---|---|
| `/start` | приветствие и список команд |
| `/add AAPL` | добавить тикер в свой список отслеживания |
| `/remove AAPL` | убрать тикер из списка |
| `/list` | показать текущий список |
| `/check AAPL` | разовый анализ прямо сейчас (не дожидаясь расписания) |
| `/history` | последние 10 отправленных сигналов |
| `/backtest AAPL` | проверка стратегии на исторических данных (~3 года), сравнение с Buy & Hold |
| `/accuracy` | честная точность прошлых сигналов — сверка прогнозов с реальными ценами |
| `/retrain AAPL` | принудительно переобучить модель прямо сейчас (не дожидаясь недельного цикла) |

Ежедневно в заданное время (по умолчанию 9:30, настраивается в `.env`)
бот автоматически анализирует все тикеры из твоего списка и присылает
уведомление, только если сигнал BUY или SELL (чтобы не спамить каждый день).

## Тесты и CI (GitHub Actions)

В проекте есть автоматические тесты (`tests/`, на pytest) и workflow
GitHub Actions (`.github/workflows/ci.yml`), который запускает их в
чистом Python-окружении при каждом push и pull request в `main`.

**Зачем это нужно:** без CI ошибки (несовместимая версия пакета,
опечатка, сломанная логика после правки) обнаруживаются только на
Render — то есть в продакшене, посреди рабочего деплоя. CI ловит их на
GitHub раньше, за секунды, без риска для работающего бота.

Что проверяет CI:
- Синтаксис всех модулей (`python -m py_compile *.py`)
- ~30 тестов на синтетических данных: технические индикаторы, point-in-time
  корректность фундаментальных данных (нет утечки будущего), правила
  BUY/SELL/HOLD и все модификаторы (sentiment/рынок/отчётность),
  ATR-риски и сайзинг позиции, кэширование моделей, честная сверка
  точности сигналов
- Отсутствие конфликтов версий в `requirements.txt` (`pip check`)

Тесты не делают реальных сетевых запросов — везде, где нужны котировки
или отчётность, используются синтетические данные и monkeypatch
(см. `tests/conftest.py`). Это делает CI быстрым (обычно < 1 минуты) и
не зависящим от доступности yfinance или лимитов запросов.

**Запуск тестов локально:**
```bash
pip install -r requirements.txt -r requirements-dev.txt
pytest tests/ -v
```

**Зависимости разделены на три файла:**
- `requirements.txt` — то, что нужно боту в продакшене всегда
- `requirements-sentiment.txt` — опционально, только для FinBERT
  (тяжёлые `torch`/`transformers`, ~1-2 ГБ)
- `requirements-dev.txt` — только `pytest`, нужен для тестов/CI, не для
  реальной работы бота

## Как это работает технически

1. **data_fetcher.py** — загружает 5 лет дневных котировок через yfinance
2. **features.py** — считает технические индикаторы (SMA, RSI, MACD,
   Bollinger Bands, волатильность, моментум)
3. **fundamentals.py** — загружает фундаментальные показатели (рост
   выручки год к году, чистая маржа, ROE, долг/капитал) из годовой
   отчётности и присоединяет их к дневным данным с привязкой по датам
   публикации отчёта (point-in-time), чтобы не допустить утечки будущего
4. **market_context.py** — добавляет относительную силу акции против
   S&P 500 (20/60 дней) как обучающий признак, плюс определяет режим
   рынка (бычий/медвежий/боковой) для ограничивающей логики в сигнале
5. **model.py** — для каждого из 4 горизонтов (1н/2н/1м/3м) обучается
   отдельный RandomForestClassifier на 16 признаках (10 технических +
   2 рыночных + 4 фундаментальных), предсказывающий класс
   (рост/падение/нейтрально) с оценкой вероятности (confidence),
   конкретной ценовой целью, диапазоном и уровнями риска (ATR-based
   стоп-лосс/тейк-профит из risk_management.py)
6. **signal_logic.py** — если 3+ из 4 горизонтов согласованно указывают
   на рост/падение и уверенность модели выше порога — формируется
   сигнал BUY/SELL; медвежий рынок или резко противоречащие новости
   поднимают планку до единогласия (4/4) или понижают сигнал до HOLD;
   приближающаяся отчётность (earnings.py) добавляет явное предупреждение
7. **telegram_bot.py** — по расписанию прогоняет весь watchlist каждого
   пользователя и присылает только значимые сигналы

## Прогноз цены по горизонтам

Для каждого из 4 горизонтов (1 неделя / 2 недели / 1 месяц / 3 месяца)
агент выдаёт не абстрактную "уверенность", а конкретный ценовой ориентир:

```
• 1 месяц: ↑ $203.00–$214.60 (+6.5%, увер. 65%)
```

- **Диапазон цены** строится на исторической волатильности исходов того
  же класса (рост/падение/нейтрально) для этого тикера — если раньше
  такие движения сопровождались большим разбросом, диапазон шире.
  Это статистическая оценка, не гарантия — цена вполне может выйти за
  пределы диапазона, особенно на новостных шоках
- **Ключевые факторы** — под прогнозом показываются 3 признака
  (индикатора), которые сильнее всего повлияли на решение модели
  (`feature_importances_` у RandomForest), с их текущими значениями.
  Например: *"момент за 60 дней (+0.21), цена выше SMA200 (+0.22)"* —
  это превращает прогноз из "чёрного ящика" в объяснимый: видно, ПОЧЕМУ
  модель так считает, а не только ЧТО она предсказывает

## Фундаментальные данные

Технические индикаторы (RSI, MACD, скользящие средние) хорошо ловят
краткосрочные движения (1-2 недели), но для горизонта в 1-3 месяца
важнее фундаментальное здоровье компании. Добавлены 4 метрики:

- **revenue_growth_yoy** — рост выручки год к году
- **net_margin** — чистая рентабельность (Net Income / Revenue)
- **roe** — рентабельность собственного капитала
- **debt_to_equity** — долговая нагрузка (Долг / Капитал)

**Важный технический момент (point-in-time correctness):** каждая
метрика привязывается не к дате окончания отчётного периода, а к дате,
когда отчёт РЕАЛЬНО стал публично доступен (+90 дней — типичная
задержка публикации 10-K/10-Q). Без этого при обучении/бэктесте модель
"видела" бы квартальные результаты за 1-2 месяца до их фактической
публикации — грубая, но частая ошибка, которая рисует обманчиво хорошие
результаты бэктеста, не воспроизводимые в реальной торговле.

**Ограничение бесплатного источника:** yfinance даёт глубину годовой
отчётности примерно на 4 года назад. Для более длинной истории
(нужна для качественного backtest на 10+ лет) потребуется платный
источник данных, например SEC EDGAR API с полным архивом отчётности.

В команде `/check AAPL` теперь также показывается снимок последних
известных фундаментальных показателей — для контекста, на основании
чего строится долгосрочный прогноз.

## Рыночный контекст, риск-менеджмент и отчётность

Три дополнения делают агента ближе к тому, как рассуждает реальный
аналитик — не просто "паттерн в графике этой акции", а полная картина:
рынок в целом, риск сделки и известные источники повышенной неопределённости.

**Относительная сила против рынка (`market_context.py`)** — модель теперь
знает не только как ведёт себя сама акция, но и обгоняет ли она рынок
(excess return против S&P 500 за 20 и 60 дней). Это отделяет собственную
силу акции ("alpha") от того, что "просто весь рынок растёт" ("beta") —
признаки участвуют в обучении наравне с техническими и фундаментальными.

**Режим рынка** — определяется по SPY (цена выше/ниже 200-дневной средней
+ моментум): бычий / медвежий / боковой. Работает как ограничивающий
фактор в `signal_logic.py`: BUY на медвежьем рынке требует ЕДИНОГЛАСНОГО
согласия всех 4 горизонтов (4/4, а не обычных 3/4) — планка доказательств
выше, когда контекст против сделки.

История SPY нужна при анализе каждого тикера, поэтому она кэшируется в
памяти процесса — но **со сроком жизни 6 часов**
(`MARKET_CACHE_TTL`). Это важно именно для бота: он работает на сервере
неделями без перезапуска, и кэш без срока жизни означал бы, что режим
рынка навсегда посчитан по котировкам на дату запуска процесса —
ежедневный прогон продолжал бы выдавать сигналы по всё более
устаревшей картине рынка, не выдавая ни одной ошибки в логах. Если
обновить данные не удалось (нет сети), используются прошлые данные из
кэша с предупреждением в лог — устаревшие цифры полезнее, чем режим
"Н/д" и обнулённая относительная сила.

**Риск-менеджмент (`risk_management.py`)** — рекомендация теперь не
заканчивается на "BUY", а включает:
- **Стоп-лосс и тейк-профит** на основе ATR (Average True Range —
  стандартная мера волатильности, учитывающая гэпы)
- **Соотношение риск/прибыль** (например, 1:1.7)
- **Рекомендуемый размер позиции** — по формуле фиксированного риска
  (по умолчанию не более 1% капитала на сделку), так что срабатывание
  стоп-лосса ограничивает убыток заданным процентом, а не случайной суммой

**Предупреждение об отчётности (`earnings.py`)** — если в горизонт
прогноза попадает дата ближайшей квартальной отчётности, сообщение явно
предупреждает об этом: отчётность — один из немногих моментов, когда цена
может резко скакнуть по причинам, которые технический анализ по
определению не предсказывает (реакция на неожиданность, а не на паттерн).

## Sentiment-анализ новостей (FinBERT)

FinBERT — модель BERT, дообученная на финансовых текстах для классификации
тональности новостей (Positive/Negative/Neutral). Работает иначе, чем
фундаментал и техника: это **живой (real-time) модификатор** итогового
сигнала, а не признак для обучения модели.

**Почему не признак для обучения:** бесплатных источников с историческим
архивом новостей за несколько лет с точной привязкой по датам не
существует (в отличие от котировок и годовой отчётности). yfinance даёт
только последние ~10-20 новостей без глубины. Обучать модель на этом
означало бы либо утечку данных, либо обучение почти всегда на нулевом
значении — оба варианта хуже честного использования sentiment только
"здесь и сейчас".

**Как влияет на решение:** если технический анализ даёт уверенный BUY,
но свежие новости резко негативны (score < -0.3) — сигнал понижается до
HOLD. Аналогично для SELL при резко позитивных новостях. Sentiment не
создаёт сигнал сам по себе — только тормозит уже принятое решение при
явном противоречии, чтобы не покупать/продавать вопреки очевидным
свежим новостям, которые модель, обученная на исторических котировках,
не видит.

**Установка:** требует `transformers` и `torch`, вынесенные в отдельный
файл `requirements-sentiment.txt` (не ставятся по умолчанию — см. раздел
"Тесты и CI" выше). Без них бот работает нормально — просто sentiment
всегда нейтрален (0.0), сигналы формируются только на технике и
фундаментале. Первая загрузка модели FinBERT — это скачивание ~400 МБ
весов, происходит один раз при первом реальном использовании.

```bash
pip install -r requirements-sentiment.txt
```

## Кэширование моделей и еженедельное автопереобучение

Раньше RandomForest переобучался заново при КАЖДОМ вызове прогноза — при
каждом `/check` и при каждом ежедневном прогоне по всем тикерам всех
пользователей. Это расточительно: рыночные закономерности не меняются
настолько быстро, чтобы требовать переобучения каждый день.

Теперь (`model_store.py`):
- Модели обучаются **раз в неделю** (по умолчанию — воскресенье, 03:00
  по времени сервера) отдельным планировщиком `weekly_retrain_job`,
  который проходит по всем тикерам из watchlist всех пользователей
- Обученные модели сохраняются на диск (`models_cache/<TICKER>/`) вместе
  с датой обучения
- В течение недели `/check` и ежедневный анализ используют кэш — это
  в разы быстрее, чем обучение с нуля (в тестах — ускорение ~8x)
- Если кэш старше 7 дней или отсутствует — модель обучается автоматически
  "на лету" при следующем запросе, никакого ручного вмешательства не
  требуется
- То же происходит, если файл кэша **не удаётся прочитать** — например,
  после обновления зависимостей кэш остался записанным другой версией
  scikit-learn и формат pickle стал несовместим. Такой кэш считается
  недействительным, и модель переобучается. Это важно для сервера с
  постоянным диском (Render): иначе каждый запуск после обновления
  падал бы на чтении кэша, пока папку не удалят вручную
- Команда `/retrain AAPL` позволяет принудительно переобучить конкретный
  тикер прямо сейчас, не дожидаясь недельного цикла

## Честная оценка точности (`/accuracy`)

Модель может "быть уверена на 70%" и при этом стабильно ошибаться —
уверенность модели (confidence) и реальная точность прогнозов часто
расходятся. Единственный способ узнать правду — сверить прошлые
прогнозы с тем, что случилось на самом деле.

Как это работает (`accuracy.py`):
1. Каждый раз, когда бот присылает сигнал (через `/check` или ежедневный
   анализ), прогноз по всем 4 горизонтам сохраняется в БД
   (`signals_history`) вместе с ценой на момент сигнала
2. Команда `/accuracy` проходит по всей истории сигналов пользователя и
   для каждого горизонта, по которому уже прошло достаточно календарного
   времени (например, для 1-месячного прогноза — не раньше чем через
   месяц), подгружает фактическую цену на эту дату
3. Сравнивает направление, которое предсказала модель, с тем, что
   произошло по факту — и считает долю верных предсказаний по каждому
   горизонту
4. Отдельно считает **практическую эффективность** — сколько из
   BUY/SELL сигналов на горизонте 1 месяц оказались реально прибыльными

Сигналы, по которым горизонт ещё не наступил, честно пропускаются, а не
додумываются — если прогноз на 3 месяца сделан неделю назад, "оценивать"
его пока нечем.

**Повторы не засоряют статистику.** Один и тот же сигнал по бумаге
держится неделями, а ежедневный прогон запускается каждый день — без
защиты одна долгоиграющая идея превратилась бы в десятки одинаковых
записей и перевесила бы в статистике все остальные решения модели.
Поэтому `db.log_signal` не добавляет в историю повтор той же пары
(тикер, действие) в пределах недели — это самый короткий горизонт
прогноза (`SIGNAL_DEDUP_DAYS`). Смена решения (BUY → SELL) и сигнал по
другой бумаге записываются всегда: это новая информация.

**Как читать результат:** случайное угадывание направления даёт ~50%.
Если точность заметно ниже — сигналам модели по этим тикерам пока не
стоит доверять реальными деньгами, независимо от того, что показывает
поле "уверенность" в самом сигнале.

## Деплой через GitHub и Render

### Шаг 1. Залить проект в GitHub

```bash
cd stock-agent
git init
git add .
git commit -m "Initial commit: stock agent bot"
```

`.gitignore` уже настроен — файл `.env` с вашим токеном в репозиторий не попадёт.

Создайте пустой репозиторий на [github.com/new](https://github.com/new)
(без README/gitignore — они уже есть локально), затем:

```bash
git remote add origin https://github.com/<ваш-username>/stock-agent.git
git branch -M main
git push -u origin main
```

После push автоматически запустится CI (`.github/workflows/ci.yml`) —
проверить результат можно во вкладке **Actions** репозитория на GitHub.
Зелёная галочка значит, что код прошёл ~30 тестов в чистом
Python-окружении и синтаксически корректен ещё до того, как вы решите
его деплоить.

### Шаг 2. Подключить репозиторий к Render

1. Зарегистрируйтесь на [render.com](https://render.com), войдите через GitHub
2. **New +** → **Blueprint**
3. Выберите свой репозиторий `stock-agent` — Render автоматически найдёт
   `render.yaml` и предложит создать описанный в нём Background Worker
4. При создании Render попросит ввести `TELEGRAM_TOKEN` вручную (он
   помечен `sync: false` в render.yaml именно поэтому — чтобы не хранить
   секрет в репозитории)
5. Нажмите **Apply** — Render соберёт окружение (`pip install -r requirements.txt`)
   и запустит `python telegram_bot.py`

**Важно про тариф:** Background Worker не входит в бесплатный план Render
(нужен от ~$7/мес). Free tier есть только у Web Service, но он "засыпает"
после 15 минут простоя — для бота с постоянным опросом Telegram (long
polling) это означает разрывы связи, поэтому для стабильной работы нужен
именно Worker.

**Важно про диск:** `render.yaml` уже подключает постоянный диск
(`/data`, 1 ГБ) и направляет туда базу (`watchlist.db`) и кэш моделей
(`models_cache/`) через переменные `DB_PATH` и `MODELS_CACHE_DIR`. Без
этого диска данные стирались бы при каждом передеплое — с ним watchlist
и обученные модели переживают обновления кода.

### Шаг 3. Проверить, что бот отвечает

Откройте Telegram, найдите своего бота, отправьте `/start`. Логи запуска
и работы бота смотрите во вкладке **Logs** в Render Dashboard — там же
видно ошибки, если что-то пошло не так (например, неверный токен).

### Обновление бота после изменений в коде

Перед пушем полезно прогнать тесты локально — быстрее, чем ждать CI:
```bash
pytest tests/ -v
```

```bash
git add .
git commit -m "описание изменений"
git push
```

GitHub Actions прогонит тесты повторно (независимая проверка), а Render
отслеживает ветку `main` и передеплоивает автоматически при каждом push —
эти два процесса идут параллельно и не блокируют друг друга.

### Типичная ошибка сборки: `metadata-generation-failed` для pandas

Если билд падает с `error: metadata-generation-failed` и упоминанием
`pandas` (pip пытается собрать пакет из исходников через ninja/meson и
падает) — причина почти всегда в том, что Render использует более новую
версию Python, для которой ещё нет готового wheel-файла под зафиксированную
в `requirements.txt` версию `pandas`.

**Исправление** (уже встроено в проект): файл `runtime.txt` в корне
репозитория закрепляет `python-3.13.15`, а `render.yaml` дублирует это
через `PYTHON_VERSION=3.13.15`. Если ошибка всё же повторяется:
1. Убедитесь, что `runtime.txt` реально закоммичен и запушен в репозиторий
2. В Render Dashboard → **Environment** проверьте, что `PYTHON_VERSION=3.13.15` установлена
3. Нажмите **Manual Deploy** → **Clear build cache & deploy** — иногда
   Render кэширует предыдущую (сломанную) попытку сборки

## Backtest — проверка стратегии на истории

Модуль `backtest.py` прогоняет стратегию по историческим данным методом
**walk-forward**: на каждую точку ребалансировки (по умолчанию раз в месяц)
модель обучается ТОЛЬКО на данных ДО этой даты — без заглядывания в
будущее (это частая ошибка бэктестов, дающая обманчиво хорошие цифры).

Симулируется портфель: покупка на BUY-сигнал, продажа на SELL-сигнал,
удержание позиции на HOLD. Результат сравнивается со стратегией
"купить и держать" (buy & hold) — обязательным бенчмарком.

Запуск из командной строки:
```bash
python backtest.py AAPL
python backtest.py AAPL --start 2019-01-01 --capital 10000 --save-chart
```

Метрики в отчёте:
- **Итоговая доходность** и **CAGR** (среднегодовая доходность)
- **Sharpe ratio** — доходность с поправкой на риск (волатильность).
  Выше — лучше; Sharpe стратегии ниже, чем у Buy & Hold, обычно означает,
  что дополнительная сложность стратегии не окупается
- **Max drawdown** — максимальная просадка портфеля от пика до дна.
  Критично для оценки психологической и финансовой переносимости риска
- **Win rate** — доля прибыльных сделок из закрытых пар BUY→SELL

Через Telegram доступна команда `/backtest AAPL` — она использует те же
расчёты, но с уменьшенным периодом (~3 года) ради скорости ответа бота.

**Как читать результат:** если стратегия систематически проигрывает
Buy & Hold по доходности с поправкой на риск (Sharpe) — сигналы модели
на этом тикере пока не дают реального преимущества, и полагаться на них
не стоит. Это нормальный и ожидаемый исход для baseline-модели на старте;
задача бэктеста — не дать красивую цифру, а честно показать, работает
стратегия или нет, прежде чем на неё полагаться.

## Безопасность

Проект прошёл ручной аудит на типичные классы уязвимостей (SQL-инъекции,
небезопасная десериализация, path traversal, утечки секретов,
контроль доступа). Найденное и исправленное:

- **Небезопасная десериализация (CWE-502)** — `model_store.py` использует
  `joblib`/`pickle` для хранения обученных моделей (стандартный формат
  scikit-learn), а `pickle.load` по своей природе исполняет код при
  десериализации. Добавлена проверка целостности: каждый файл кэша
  подписывается HMAC-SHA256 с локальным секретным ключом (создаётся один
  раз, никуда не передаётся). При загрузке подпись пересчитывается и
  сверяется — несовпадение трактуется как возможная подмена, и кэш
  игнорируется (модель переобучается заново), а не загружается вслепую.
  **Важно**: никогда не копируйте `models_cache/` с чужого компьютера
  или из общей/синхронизируемой папки — переносите только вместе с
  остальными файлами своей собственной установки.
- **Path traversal (CWE-22)** — тикер, вводимый пользователем, в итоге
  становится частью пути к файлу кэша моделей. Добавлен модуль
  `ticker_validation.py` со строгой проверкой формата (только буквы,
  цифры, точка, дефис; 1-10 символов; плюс блокировка зарезервированных
  имён устройств Windows типа `CON`/`PRN`), применяется на входе
  (`is_valid_ticker`) и повторно, независимо, в самой уязвимой точке
  (`model_store._ticker_dir`) — по принципу defense-in-depth, не
  полагаясь на то, что вызывающий код уже всё проверил.
- **Отсутствие контроля доступа к Telegram-боту** — по умолчанию бот
  отвечал ЛЮБОМУ пользователю Telegram, который его найдёт: не утечка
  чужих данных (у каждого свой изолированный watchlist в БД), но вектор
  злоупотребления вычислительными ресурсами (`/backtest` — десятки
  переобучений моделей подряд), что на платных тарифах хостинга означает
  реальные деньги. Добавлена переменная `ALLOWED_TELEGRAM_USER_IDS`
  в `.env` — если задать свой Telegram user_id, бот будет отвечать
  только вам. Если оставить пустой (по умолчанию, для обратной
  совместимости) — при старте в лог выводится явное предупреждение.

**Проверено и признано безопасным:**
- Все SQL-запросы в `db.py` параметризованы (`?`-плейсхолдеры) — SQL-
  инъекции исключены
- Нигде не используются `eval`, `exec`, `os.system`, `subprocess`,
  `shell=True`
- Секреты (Telegram-токен) читаются только из переменных окружения,
  нигде не хардкожены и не попадают в логи; `.env` исключён из git
  через `.gitignore`
- SSL/TLS-проверка сертификатов нигде не отключается

**На что стоит обратить внимание самостоятельно:**
- `numpy==1.26.4` в `requirements.txt` — эта ветка NumPy 1.x достигла
  конца поддержки; рекомендуется периодически проверять зафиксированные
  версии зависимостей на известные уязвимости (например, через
  `pip install pip-audit && pip-audit`) и обновлять по мере готовности
  (переход на NumPy 2.x может потребовать проверки совместимости с
  зафиксированными версиями pandas/scikit-learn — сознательно не делаю
  этот breaking change без вашего запроса)
- Собранный `.exe` (PyInstaller) не подписан цифровой подписью — это
  нормально для личного использования, но может вызывать
  предупреждения антивируса при распространении другим людям; для
  публичного распространения рассмотрите code signing
- `sp500_universe.py` обращается к Wikipedia напрямую (парсинг HTML-
  таблицы через `pandas.read_html`) — код ничего не исполняет из
  полученных данных, только читает текстовые значения тикеров, но само
  наличие сетевого запроса к внешнему источнику стоит иметь в виду при
  оценке модели угроз

Тесты для всех перечисленных исправлений — в `tests/test_ticker_validation.py`
и обновлённом `tests/test_model_store.py`.
